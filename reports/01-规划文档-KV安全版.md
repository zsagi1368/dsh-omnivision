## 一、核心架构创新：Vision Pre-Step Bridge

### 1.1 问题诊断

现有三种路由模式对KV Cache的影响：

| 模式 | 图片进入DeepSeek请求？ | KV Cache影响 | 原因 |
|------|---------------------|-------------|------|
| 工具模式（tools-first） | ❌ 否 | ✅ 无影响 | 图片替换为文字标记 |
| 整轮路由（full-turn） | ✅ 是 | ⚠️ 有影响 | 改变请求前缀结构 |
| 反向路由（reverse-route） | ✅ 是 | ⚠️ 有影响 | 创建新模型别名 |

**根本问题**：后两种模式让图片进入DeepSeek请求，必然改变请求结构，导致KV Cache失效。

### 1.2 解决方案：统一前置桥接器

```
无论用户选什么模式，插件都在DeepSeek请求发出之前拦截：
1. 检测图片附件
2. 异步调用vision pipeline处理
3. 将图片替换为结构化文字描述
4. 发送纯文本请求给DeepSeek
```

**结果**：DeepSeek的请求结构永远不变，KV Cache完全不受影响。

### 1.3 核心模块：VisionBridge

```typescript
// src/bridge/vision-bridge.ts
export class VisionBridge {
  private imageBuffer = new Map<string, ImageProcessingTask>();
  private resultCache = new Map<string, string>();
  
  /**
   * 前置处理：在DeepSeek请求发出之前调用
   * 返回改写后的messages数组（图片全部替换为文字）
   */
  async preProcessMessages(
    messages: DshMessage[],
    session: Session
  ): Promise<ProcessedMessages> {
    const unchanged: DshMessage[] = [];
    const changed: DshMessage[] = [];
    
    for (const msg of messages) {
      const images = extractImageAttachments(msg);
      
      if (images.length === 0) {
        unchanged.push(msg);
        continue;
      }
      
      // 异步处理图片，等待完成
      const descriptions = await this.processImages(images, msg, session);
      const rewritten = rewriteWithDescriptions(msg, descriptions);
      changed.push(rewritten);
    }
    
    return {
      messages: [...unchanged, ...changed],
      imageCount: changed.length,
      descriptions: changed.map(m => extractDescription(m)),
    };
  }
  
  /**
   * 核心：将图片转换为结构化文字描述
   */
  private async processImages(
    images: ImageAttachment[],
    originalMsg: DshMessage,
    session: Session
  ): Promise<VisionDescription[]> {
    return Promise.all(
      images.map(async (img) => {
        const cacheKey = this.createCacheKey(img, originalMsg.content);
        
        // 1. 查缓存（session级L1 + disk级L2）
        const cached = await this.cache.get(cacheKey);
        if (cached) return parseDescription(cached);
        
        // 2. 调用vision pipeline（带failover链）
        const result = await this.visionPipeline.run({
          images: [img],
          query: originalMsg.content,
          mode: this.mode,
        });
        
        // 3. 缓存结果
        await this.cache.set(cacheKey, serialize(result));
        
        return result.description;
      })
    );
  }
  
  private createCacheKey(img: ImageAttachment, query: string): string {
    return createHash('sha256')
      .update(img.contentHash)
      .update(query || '')
      .digest('hex');
  }
}
```

## 二、消息改写与影子历史

### 2.1 消息改写逻辑

```typescript
// src/bridge/message-rewriter.ts

/**
 * 将包含图片的消息改写为纯文本消息
 */
export function rewriteWithDescriptions(
  original: DshMessage,
  descriptions: VisionDescription[]
): DshMessage {
  let newContent = original.content;
  
  for (let i = 0; i < descriptions.length; i++) {
    const desc = descriptions[i];
    const marker = `[已识图${i + 1}: ${desc.summary}]`;
    newContent = `${newContent}\n\n${marker}`;
  }
  
  return {
    ...original,
    content: newContent,
    attachments: [],  // 移除所有图片附件
  };
}
```

### 2.2 影子历史机制

```typescript
// src/bridge/shadow-history.ts

/**
 * 保持session历史的完整性
 * 用户界面显示原始图片，但模型看到的是文字
 */
export function createShadowReplacement(
  originalEvent: DshEvent,
  processedEvent: DshEvent
): ShadowReplacement {
  return {
    // 用户看到的界面：保留原始图片（美观）
    surfaceOp: { op: 'keep', eventId: originalEvent.id },
    
    // 模型实际收到的：文本版本（保护KV Cache）
    modelOp: { op: 'replace', eventId: processedEvent.id },
  };
}
```

```typescript
export type VisionMode = 
  | 'auto'         // 全自动：图片自动转文字，用户无感

export interface VisionModeStrategy {
  name: VisionMode;
  
  /**
   * 处理消息：返回改写后的消息

   * 是否启用工具暴露
   */

  /**
   * KV Cache影响：始终为false
   */
  kvCacheImpact: false;
}
```

```typescript
// src/modes/auto.ts

export const AutoMode: VisionModeStrategy = {
  name: 'auto',
  exposeTools: false,
  kvCacheImpact: false,
  
  async process(message, ctx) {
    const images = extractImageAttachments(message);
    if (images.length === 0) return { unchanged: true };
```

### 3.3 Interactive模式

```typescript
// src/modes/interactive.ts

export const InteractiveMode: VisionModeStrategy = {
  name: 'interactive',
  exposeTools: true,
  kvCacheImpact: false,
  
  async process(message, ctx) {
    const images = extractImageAttachments(message);
    if (images.length === 0) return { unchanged: true };
    
    // 1. 生成简要摘要（不阻塞）
    const summary = await ctx.visionBridge.processSummary(images);
    
    // 2. 注入提示 + 移除图片
    const enrichedContent = `${message.content}\n\n[__vision__: 已识图摘要: ${summary}]\n[__vision__: 需要详细分析？调用vision_describe/get_more_details工具]\n`;
    
    return { 
      rewritten: { ...message, content: enrichedContent, attachments: [] },
      toolHints: ['vision_describe', 'vision_ground', 'vision_detect']
    };
  },
};

/**
 * 用户体验：
 * 1. 用户贴图片 + 提问
 * 2. 插件生成摘要，注入消息
 * 3. DeepSeek先看到摘要（快速回答）
 * 4. 如需详细分析，模型可调用工具
 * 
 * KV Cache：完全不受影响（图片始终不进入请求）
 */
```

## 七、安全设计

### 7.1 路径策略（PathPolicy）

```typescript
export class PathPolicy {
  allowInput(path: string): boolean {
    const resolved = path.resolve(path);
    return (
      resolved.startsWith(this.workspace) ||
      resolved.startsWith(this.tempDir) ||
      [...this.allowedDirs].some(d => resolved.startsWith(d))
    );
  }
  
  rejectSymlink(path: string): void {
    if (fs.lstatSync(path).isSymbolicLink()) {
      throw new VisionError('PATH_SYMLINK_DENIED', `Symbolic links are not allowed: ${path}`);
    }
  }
}
```

### 7.2 SSRF防护

```typescript
export async function assertSafeRemoteTarget(url: string): Promise<PinnedTarget> {
  const parsed = new URL(url);
  
  // 协议白名单
  if (!['http:', 'https:'].includes(parsed.protocol)) {
    throw new VisionError('SSRF_UNSUPPORTED_PROTOCOL', `Unsupported protocol: ${parsed.protocol}`);
  }
  
  // IP校验
  const ip = await dnsLookup(parsed.hostname);
  if (isPrivateOrReserved(ip)) {
    throw new VisionError('SSRF_PRIVATE_IP', `Blocked private/reserved IP: ${ip}`);
  }
  
  // DNS rebinding防护
  return { url, ip, dispatcher: pinnedDispatcher({ host: parsed.hostname, ip }) };
}
```

### 7.3 三层凭据脱敏

```typescript
export function redactSecrets(text: string, knownSecrets: string[]): string {
  let out = text;
  
  // Layer 1: 精确匹配
  for (const secret of knownSecrets) {
    out = out.replaceAll(secret, '[REDACTED]');
  }
  
  // Layer 2: token形状正则
  out = out.replace(/(?:sk-|pk-)[a-zA-Z0-9]{20,}/g, '[REDACTED_KEY]');
  out = out.replace(/Bearer\s+[a-zA-Z0-9._-]{20,}/g, 'Bearer [REDACTED]');
  
  // Layer 3: URL userinfo
  out = out.replace(/(https?:\/\/)([^:@]+):([^@]+)(@)/g, '$1***:***$4');
  
  return out;
}
```

```typescript
export class VisionCircuitBreaker {
  private state = new Map<string, CircuitState>();
  
  isBlocked(provider: string): boolean {
    const s = this.state.get(provider);
    if (!s) return false;
    if (s.blockedUntil > Date.now()) return true;
    this.state.delete(provider);
    return false;
  }
  
  record(provider: string, failure: VisionFailure): void {
    // AUTH/REGION/TOS → TTL过期或凭证变化才重置
    // RATE_LIMIT/QUOTA → Retry-After感知的冷却期
    // INVALID_REQUEST → turn结束重置
  }
}
```

## 九、缓存系统

### 9.1 多层缓存架构

```
┌─────────────────────────────────────────────────────────┐
│                    L1: Session Cache                     │
│  • 内存：WeakMap<Session, Map<CacheKey, Result>>         │
│  • 容量：64 entries / 256KB                              │
│  • TTL：1小时 idle                                       │
│  • 用途：同session重复调用免花钱                          │
├─────────────────────────────────────────────────────────┤
│                    L2: Disk Cache                        │
│  • 路径：$DSH_HOME/cache/omnivision/                    │
│  • 格式：JSON + 原图字节                                 │
│  • 容量：200 entries / 512MB                             │
│  • 淘汰：LRU（按访问权重）                               │
│  • 用途：跨session复用                                   │
├─────────────────────────────────────────────────────────┤
│                    L3: Pre-compute Cache                 │
│  • 仅针对vision_bootstrap结果                           │
│  • 持久化到session storage                              │
│  • 用途：避免重复bootstrap                                │
└─────────────────────────────────────────────────────────┘
```

## 十一、KV Cache安全保障总结

| 设计点 | 如何保护KV Cache |
|--------|-----------------|
| **Pre-Step Bridge** | 图片在请求发出前就转换为文字，DeepSeek永远看不到图片 |
| **Shadow History** | UI显示图片，模型收到文字，两者分离 |
| **统一消息结构** | 无论哪种模式，DeepSeek请求结构不变 |
| **稳定缓存key** | 同样的图片+问题 → 同样的缓存命中，减少重复调用 |
| **异步非阻塞** | 图片处理在后台进行，不阻塞主请求流 |

**核心保证**：
> 无论用户选择auto/interactive/manual模式，无论配置什么provider，DeepSeek收到的请求**永远是纯文本**，KV Cache**完全不受影响**。
